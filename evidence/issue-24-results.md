# Issue #24 implementation evidence

## Implemented

`src/supplychainworld/agent_runner.py` adds `ObservableRunner`, `replay` and `scripted_policy`. `OperationalWorld` and the #23 baselines are unchanged. Tools: `read_state` (sections all, clock, state, rules), `read_recovery_offers`, `read_scorecard`, `commit_recovery`, `release_production`, `advance_day`, grouped into read, commit and advance authority classes that can be restricted per runner. Every call is recorded with day, arguments, accepted flag, rejection category and reason, visible state before and after, field-level state changes and new events. The agent view carries `clock` (current day, horizon, days remaining, phase, final-day flag) so five-day and fifteen-day episodes are equally visible to the agent.

Rejection categories: `hidden_state`, `unknown_tool`, `invalid_arguments`, `authority`, `repeated_commitment` (duplicate recovery or release, reused action id), `deadline`, `invalid_action` (quantity, capacity, material, budget, closed episode), `unavailable` (scorecard before completion), `attempt_limit`, and `agent_error`. Runner-level refusals never reach the world. World-level refusals are also in the world history and leave operational state unchanged.

## Tested

Actual command: `PYTHONPATH=src python -m unittest discover -s tests -v`. All 63 tests passed (39 existing, 24 new in `tests/test_agent_runner.py`). See [raw output](issue-24-tests.log). New tests cover: horizon and clock visibility for 5 and 15 days; deadline visible only after notice and enforced; reads not advancing time; authority classes; hidden-state probes (tool, section, argument); absence of hidden mechanics in pre-notice views; invalid, over-budget and no-material actions; repeated commitments with no duplicate charge; reused action ids; attempt limits; chronological transcript contents; recovery changing actual receipts (maintain: primary day 4; expedite: primary day 2; alternate: alternate day 2 plus primary day 4); replay of 5 and 15-day runs, including rejected attempts; tamper detection; agent failure history; detached views.

Scripted-policy comparison costs through the tool interface match #23: five-day 120/24/40, fifteen-day 200/24/40 (maintain/expedite/alternate). Actual transcripts and replay results: [issue-24-traces.json](issue-24-traces.json), generated by `PYTHONPATH=src python scripts/run_agent_runner_traces.py`. All six policy runs replayed identically, and a rejection demonstration (hidden probe, overproduction, expedite, second recovery, release, advance) replays identically.

## Limitations

- Evidence covers one synthetic scenario family. It is not a generalization, model-ability or training-improvement claim; the policies are scripted, not an LLM, and no paid calls were made.
- The boundary is not hostile-code isolation. The runner holds the world in the same process; a malicious in-process agent could read it. Hidden-state rejection is a name and argument filter plus a view that never contains scenario mechanics, not a sandbox.
- The hidden-probe filter is keyword based and so is conservative; unknown names are still rejected as unknown tools.
- Replay requires the same scenario configuration via `world_factory`; transcripts do not embed hidden scenario parameters.
- Independent checking (#25) and the complete scenario gate (#26) are not claimed. Screenshots were not captured; none are claimed.
