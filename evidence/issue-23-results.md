# Issue #23 implementation evidence

The five-day and fifteen-day synthetic situations now have separate [scenario inputs](../fixtures/dynamic/supplier-delay-inputs.json) and manually calculated [expected ledgers](../fixtures/dynamic/supplier-delay-expected.json). Three policies act using visible observations, not expected outputs or future event configuration. Their actual observations, actions, event history, daily closes and scorecards are in [issue-23-traces.json](issue-23-traces.json); the compact [scorecards](issue-23-scorecards.json) are derived from those runs.

The five-day fixture's maintain/expedite/alternate comparison costs are 120/24/40, with on-time quantities 4/12/12 and ending component stocks 0/0/8. In the distinct fifteen-day fixture, the actual delay notice and recovery occur on day 6, promised/expedited/alternate receipt day 8, delayed primary receipt day 12, and due date day 10. Its hand-calculated maintain/expedite/alternate costs are 200/24/40, and the corresponding on-time/ending-stock quantities remain 4/12/12 and 0/0/8. The $200 penalty reflects 8, 8 and 4 overdue units at three respective close-of-day assessments.

Actual local command: `PYTHONPATH=src python -m unittest discover -s tests -v`. All 13 current tests passed, including eight existing kernel tests and five new fixture tests, with 6 policy subcases. See [raw output](issue-23-tests.log). Tests cover the explicit event dates and daily ledgers, normal no-disruption operation, initial pre-notice state and version fields, hidden-future observations, input validation and deterministic full traces.

The engine keeps the previous public constructor defaults and exposes a validated scenario configuration. It now records initial opening before the day-one notice, exposes current visible business rules and recovery offers when known, and supports event/deadline dates beyond day five. This also addresses the normal-operations, initial-state and version gaps identified during #22 review. User-specified horizons remain configurable.

Limitations: this is a single-product synthetic model, not a general supply-chain simulator. Delay notices and recovery commitments must occur before the originally promised arrival; late discovery of missed delivery is not yet modeled. The scripted policies operate through an in-process object and the observation interface is not a security sandbox against malicious Python. No independent checker (#25), hostile agent isolation/replay (#24), practitioner validation, teacher model, paid API call or fine-tuning evaluation is claimed. Input fixture numbers are provisional. These public test fixtures and traces are not sealed evaluation cases.
