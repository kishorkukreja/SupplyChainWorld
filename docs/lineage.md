# Lineage and private evaluation

Create a `LineageRegistry`, then call `assign(source_case, template, ancestry=(), split=None)` **before expanding variants**. The frozen assignment supplies `lineage` and `split` for every descendant Task. Split selection is a stable salted hash unless explicitly planned. A shared source, template or ancestor inherits its registered split. Joining two allocated groups fails and requires rebuilding the manifest before generation. Use stable, honest template/source identifiers; inventing a fresh template ID does not establish independence. A registry is scoped to the complete experiment, not recreated per instance. Persist `manifest()` before agent attempts; it contains every source/template provenance assignment, including multiple entries in one lineage. `verify(task, assignment)` checks declared membership.

`overlap_report([(task, world), ...])` checks cross-split pairs. Business fingerprints discard names/seed/row ordering, anchor dates to the world's planning date, and compare business records. Structural fingerprints additionally bucket magnitudes and dates, retaining active constraints, commercial missingness and eligibility. These are conservative review checks, not proofs of graph isomorphism: ID removal can overflag different supplier relationships. Exact/structural/lineage flags block admission and cannot be waived; regroup or redesign. Similar request tokens produce semantic flags. `require_resolved` requires a named reviewer, explicit allow decision and concrete reason for every semantic flag. The token heuristic cannot establish general semantic independence; record human review and do not claim embedding-based detection.

Distinct names and random quantities on the same procurement template are insufficient held-out evaluation. Use distinct business topology/constraint regimes across protected splits, then run the overlap checks. Do not resolve structural overlap by discarding difficult cases based on agent performance.

`PrivateStore(external_root, repository_root)` rejects repository-contained stores, traversal keys and symlink record targets. It writes files with mode 0600 in a 0700 directory. Use a local external directory such as `/tmp/scw-private-<run>` for ephemeral smoke evaluation. Private payloads, expected answers and full evaluation trajectories must not enter public aggregate reports or training exports. Gitignore alone is insufficient. `agent_task_view(task)` is an allowlist excluding expected outcome and split/provenance metadata; `training_export_allowed(task)` rejects both development and evaluation tasks.

The environment exposes allowlisted observations/tools and denies hidden artifact paths. This is a logical tool boundary for trusted in-process adapters. Python plugins with arbitrary filesystem access are not sandboxed by these helpers; adversarial executable adapters require OS/process isolation. Do not hand an adapter the Task, private store, reference result or full fixture.

Run `PYTHONPATH=src python -m unittest discover -s tests -p test_lineage.py -v`.
