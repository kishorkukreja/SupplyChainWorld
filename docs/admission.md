# Admission and export

`admit(world, task, trajectory, split_assignments={lineage: split})` validates contracts, checks the predeclared assignment, rebuilds an isolated environment, compares every result and observation and artifact hash, checks actual termination and independently grades the final submission. It returns an `AdmissionResult`. Successful development/evaluation admission has no training record. Rejected runs retain explicit reasons; agent error does not imply an invalid task.

`export_jsonl(results, path, dataset_version='1.0', adjudications=())` validates IDs and lineage/exact/structural/semantic overlap before writing. Unresolved overlaps fail closed; critical cross-split collisions cannot be waived. Only accepted training records export. Export reruns admission so caller mutation cannot turn a failed record into an accepted demo. The returned manifest contains filtering counts, accepted provenance and the JSONL SHA256. Store this manifest beside JSONL. Evaluation inputs and transcripts must remain outside public repository storage.

Each JSONL line contains `messages` and separate `provenance`. User initial observation and tool outputs have `loss: false`; assistant tool calls have `loss: true`. Tool calls use role `assistant`, `tool_calls[].id`, `type: function`, function `name`, and JSON-string `arguments`. Role `tool` carries matching `tool_call_id` and JSON-string content. A training loader must honor loss flags, exclude provenance from model input and map the tool format into its provider template. There is no fabricated prose answer or chain of thought: the submitted tool call is the final supervised behavior.

Messages are built only from the environment's public observation, actual actions and replay-checked results. Expected outcome, private reference solutions, generation truth and checker reports are never teacher inputs. Provenance hashes identify the typed world/task, original trajectory and visible artifacts without embedding private task metadata.

`diagnose_failure` records explicit evidence categories: environment defect, grader defect, agent error or legitimate uncertainty. It does not infer defects from a low score. `bounded_repair` permits at most three repairs (default one) only for identified environment/grader defects. Agent errors and legitimate uncertainty trigger no repair. Repair callbacks must preserve task identity, family, expected outcome, lineage, split and all business premises. Only `task.visible_artifacts` and `task.permitted_tools` may change when explicitly listed in `allowed_changes`; typed validation still applies. The probe callback must start a fresh runner/environment; admission itself independently reconstructs an environment, while the repair helper cannot attest callback isolation. History records only that a probe was requested; unresolved rejection is retained. Diagnosis needs human or independent test evidence; a solver timeout is not infeasibility proof.

Run focused checks with `PYTHONPATH=src python -m unittest discover -s tests -p test_admission.py -v`.
